# Announcement bar and cookie consent rollout

## Existing stack and scope

EduWallet Hub is a React 19 + Vite + TanStack Router application using Supabase for persistence/auth and Cloudflare Worker infrastructure. Keep the changes on `feat/announcement-cookie-consent` until its CI/build and live browser checks pass.

## Files added or changed

- `src/lib/announcement.ts`: schema, safe URL validation, Supabase query/save helpers and defaults.
- `src/components/AnnouncementMarquee.tsx`, `src/components/announcement-marquee.css`: CSS-driven marquee; duplicate content is hidden from assistive technology, hover/focus pause, reduced-motion fallback.
- `src/routes/admin.announcements.tsx`: admin editor, reordering, schedule, colors, speed, preview, validation feedback.
- `src/routes/admin.tsx`: navigation entry.
- `src/routes/__root.tsx`: configurable bar in place of dismissible banner; analytics loading gated on analytics choice; Consent Mode defaults set in the document head.
- `src/components/CookieConsent.tsx`, `src/components/cookie-consent.css`: accept/reject/customize UI, categories, preferences dialog and persistent settings control.
- `src/components/SiteFooter.tsx`: persistent cookie settings and policy link.
- `src/routes/cookies.tsx`: editable policy template with legal placeholders.
- `src/routeTree.gen.ts`: route registration.
- `src/lib/consent.ts`: consent constants, reader and helper for vendor-gated scripts.
- `src/integrations/supabase/types.ts`: table typings.
- `supabase/migrations/20261027180000_announcement_cookie_consent.sql`: configuration/consent tables and RLS.

## Apply migration

Use the Supabase project connected to this repository (project ref in `supabase/config.toml`). Review the migration in the Supabase SQL editor or deploy through your established CLI workflow:

```sh
supabase link --project-ref jlzownnxzdwwfylaqqcn
supabase db push
```

Do not run this against a different project. Confirm the migration is recorded before testing the application. The migration seeds exactly one default row per configuration table using `ON CONFLICT DO NOTHING`; future runs do not overwrite administrator changes.

## Build and tests

```sh
bun install --frozen-lockfile
bun run lint
bun run build
```

The route tree is generated by TanStack Router during normal application builds. If its generated declarations conflict with the source route registration, regenerate it using the repository's installed router plugin rather than hand-editing the generated file.

## Announcement checks

- Visit `/admin/announcements` signed in as an authorized admin. Confirm non-admins are denied by the existing admin layout and by Supabase RLS.
- Add/edit/delete/reorder messages. Confirm no HTML is interpreted and that `javascript:`, `data:`, protocol-relative URLs, invalid colors, duplicate IDs, more than eight messages, too many characters and speed outside 12–90 seconds are rejected.
- Set a start and end time. The editor converts datetime inputs to UTC ISO timestamps; scheduling comparison on the public page uses absolute timestamps. For a reliable operator workflow, set the device timezone to the selected timezone when entering a local time.
- Check direction, loop boundary, color choices, hover/focus pause, keyboard-visible link focus and reduced motion in browser DevTools.
- Save and verify on a separate public page without redeploying. Current query stale time is 15 seconds; React Query refetch/invalidation controls the local experience.
- Check color contrast for every chosen foreground/background pair before publishing. Color validation ensures format, not WCAG contrast.

## Consent and script-gating checks

- Open DevTools > Application > Local Storage and Network. Clear `eduwallet-consent-v2` and reload.
- Before a choice, inspect Network for third-party analytics/advertising requests and Application storage for non-essential cookies. This build gates the configured Google Analytics loader, but every additional vendor or inline script must be audited and routed through explicit category gating.
- Click Reject all, reload and verify no optional tags initialize. Test Customize, toggles, Save preferences, Accept all, and footer Cookie settings.
- Test expiry by setting the stored `expiresAt` to a past timestamp, then reload. Change `CONSENT_POLICY_VERSION` in `src/lib/consent.ts` when a meaningful policy change requires new consent.
- Verify default and update consent signals in Google Tag Assistant, if a Google tag is configured. Signals must show `ad_storage`, `analytics_storage`, `ad_user_data`, and `ad_personalization`.
- Check that withdrawing analytics removes site-created loader scripts. This cannot guarantee deletion of cookies on third-party domains; vendor-specific revoke APIs/cleanup may be needed.

## Important limits and legal/vendor work still required

This custom UI is **not** a Google-certified CMP and does not implement IAB TCF. If the site will use AdSense/personalized Google ads in the EEA or UK, integrate a current Google-certified CMP with the required IAB TCF support (for example, Cloudflare Zaraz documents an IAB TCF-compliant consent option, but confirm suitability and Google's current approved-CMP list before enabling it). A custom banner does not meet that certification by itself.

The repository's static React client does not have trusted region detection early enough to enforce EEA/UK/CH-specific behavior. It establishes Consent Mode v2 defaults as denied for all visitors, which is conservative, but does not implement region-specific defaults. A reliable geo/CMP signal must be available before Google tags run to meet the exact regional requirement. Don't add a Google tag, GTM container, AdSense, Meta Pixel, or other vendor until it has been mapped to a category and tested for pre-consent network activity.

The current audit record table intentionally omits user account and IP fields; it stores pseudonymous random consent ID, category choices, policy version, jurisdiction label and timestamp. The client currently labels jurisdiction `unknown`; do not treat that as regional compliance evidence. Review the public insert policy and the database migration with your security reviewer before production, including rate-limiting/abuse expectations.

The Cookie Policy includes placeholders for the data controller/contact and vendor-specific cookie names, purposes, and retention periods. Complete it and review the Privacy Policy, applicable ePrivacy/GDPR requirements, CCPA/CPRA sale/share opt-out, data retention and lawful basis with qualified counsel. If targeted advertising or sale/sharing applies to US residents, add a working “Do Not Sell or Share My Personal Information” workflow and propagate it to vendors—not just a text link.
